Módulo 1 · Especificación de casos de uso

Iniciar sesión y administrar roles

CU-02 · Iniciar sesión

Actor: Visitante · Pre: la cuenta existe y no está bloqueada · Post: sesión vigente con token

  1. Captura nombre y contraseña.
  2. El sistema busca la cuenta en la BD, con su rol.
  3. Compara el hash PBKDF2 de la contraseña.
  4. Reinicia los intentos fallidos a cero.
  5. Crea la sesión (token, expira) en la BD.
  6. Muestra Inicio según el rol.

Excepciones: no existe o contraseña incorrecta → “Usuario o contraseña incorrectos”; al 6.º intento → bloqueo de 15 min (CU-04).

CU-30 · Administrar usuarios y roles

Actor: Administrador · Pre: sesión con rol ADMINISTRADOR · Post: rol o bloqueo actualizado en la BD

  1. Abre “Administrar usuarios”.
  2. El servidor relee el rol en la BD.
  3. Lista cuentas: empresa, rol, bloqueo.
  4. Hace o quita administrador.
  5. Desbloquea una cuenta bloqueada.

Excepciones: rol USUARIO → 403 “solo para administradores”; nadie puede quitarse su propio rol, siempre queda un administrador.

Módulo 2 · Especificación de casos de uso

Crear un espacio y unirse a él

CU-13 · Crear espacio de trabajo

Actor: Usuario · Pre: sesión vigente · Post: espacio y acceso PROPIETARIO

  1. Elige “Nuevo espacio”.
  2. Captura el nombre.
  3. El sistema crea el espacio.
  4. Le da al creador el permiso PROPIETARIO.
  5. Ofrece activar la conexión (CU-14).
  6. Muestra el espacio abierto.

Excepciones: nombre vacío o repetido → se pide corregirlo; falla al guardar → no se crea.

CU-16 · Unirse a un espacio

Actor: Usuario · Pre: espacio visible y acceso válido · Post: documento sincronizado

  1. Elige un espacio de la red (CU-15).
  2. El sistema verifica su acceso.
  3. Abre el canal de sincronización.
  4. Descarga el estado del documento.
  5. Abre el editor con su permiso.

Alternos y excepciones: sin acceso → solicita invitación; LECTURA → solo lectura; 6.º usuario → “El espacio está lleno”.

Módulo 1 · Diagrama de secuencia

Inicio de sesión con rol

1. VistaLogin envía POST /api/cuentas/sesion.

2. RepositorioUsuarios consulta Azure SQL con un JOIN a la tabla rol.

3. Contraseña incorrecta: suma el intento; al 6.º bloquea.

4. Correcta: guarda la sesión con INSERT INTO sesion.

5. Con el rol, la vista muestra o no “Administrar usuarios”.

Cada petición a /api/admin vuelve a leer el rol: si no es ADMINISTRADOR, 403.

Avance · Módulo web en la nube

Login y registro conectados a la base de datos, en Azure

Navegador o celular

HTML, CSS y JS. Guarda solo el token de sesión.

Azure App Service

Java 21 + Spring Boot, plan F1 gratuito, solo HTTPS. Revisa el rol en cada petición.

Azure SQL Database

Tablas rol, usuario, sesion y preferencias. Conexión JDBC cifrada.

Contraseñas: PBKDF2-SHA256 con sal; nunca en texto.

Secretos: en la configuración de Azure, no en el código.

Bloqueo: 15 min tras 5 intentos fallidos.
